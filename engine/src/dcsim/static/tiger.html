Forecast ledger

Forecasts are written before the night and can't be edited. Each one is scored in SQL once the night is recorded.

Plan searches

Every Optimize plan run is kept in Tiger: one row per plan tried in the hypertable search_trials. This table reads all of them: which kitchen levers the best trade-offs keep moving, and which way.

Storage

Hypertables are split into weekly chunks. Chunks older than a day move to the columnstore on a policy.

What this shows, and what it doesn't

  • The recorded nights are synthetic: the engine generated them, shaped like MetaFoodX pan data, LeanPath weigh-ins and meal swipes. Real exports load into the same tables with no code change.
  • The tables are small (six weeks of one dining hall), so the timings show the direction, not what a year of data would do. Where the columnstore or a small table already answers a question quickly, the aggregate adds nothing, and the page says so.
  • Rows newer than the last materialized bucket are read live. A change to an older night appears after the next refresh.
